# Бесплатная бета-версия на Render

Проект подготовлен к размещению одним **Node Web Service**: Fastify обслуживает API, собранный React и прямые адреса фильмов / актёров. Vite dev server на хостинге не запускается. Публикация ещё не выполнена; доступность TMDB и источников с IP Render проверяется после первого размещения.

## Что нужно от владельца

1. Войти в GitHub и Render. Можно использовать приватный репозиторий; предоставить Render доступ только к нему.
2. Создать пустой отдельный репозиторий `movieboxd`. В его корне должны лежать `package.json`, `package-lock.json`, `.node-version`, `render.yaml`, `src`, `server` и остальные исходники приложения. Не загружать весь каталог Documents или родительский репозиторий компьютера.
3. Добавить содержимое подготовленного архива `movieboxd-render-beta.zip` в репозиторий (сначала распаковать, не загружать ZIP как единственный файл). Архив не содержит `.env`, `node_modules`, локальный кеш и скриншоты. Для загрузки без терминала можно использовать GitHub Desktop; он сохранит и скрытые конфигурационные файлы. При работе через сайт GitHub проверить, что `.node-version` и `.gitignore` также загружены. Настройку репозитория и отправку исходников может выполнить агент после входа и предоставления доступа.
4. В панели Render выбрать **New → Blueprint**, подключить этот репозиторий. Render прочитает `render.yaml`; Root Directory не требуется, поскольку приложение лежит в корне репозитория.
5. В поле **TMDB_API_KEY** ввести существующий API v3 key непосредственно в Render. Его можно взять из локального `.env` или настроек TMDB. Не отправлять ключ в чат и не добавлять его в репозиторий. Blueprint специально не содержит значения. Если используется только Read Access Token, вместо поля ключа настроить секрет `TMDB_READ_ACCESS_TOKEN`; приложение поддерживает оба варианта.
6. Проверить, что выбран тариф **Free**, и запустить создание сервиса. После статуса **Live** открыть HTTPS-адрес, выданный Render. Покупка домена для бета-версии не нужна.
7. Передать агенту только публичный адрес сайта для проверки после размещения. Логины, пароли и секреты передавать не требуется.

## Настройки уже находятся в render.yaml

| Настройка | Значение |
| --- | --- |
| Runtime | Node, версия из `.node-version`: 24.21.0 |
| План | Free |
| Регион | Frankfurt |
| Build Command | `npm ci --include=dev && npm test && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| NODE_ENV | `production` |
| HOST | `0.0.0.0` |
| PORT | Выдаёт Render, вручную не задавать |
| TMDB_CACHE_PATH | `/tmp/movieboxd/tmdb.sqlite` |
| TMDB_API_KEY | Секрет, вводится в Render |

`--include=dev` нужен для TypeScript и Vite даже при `NODE_ENV=production`. `npm run build` включает проверку типов. Сбой тестов или сборки останавливает размещение. Health endpoint не расходует лимит пользовательских запросов и не вызывает внешний TMDB.

На Render сервер распознаёт автоматически установленную переменную `RENDER=true` и доверяет заголовкам адреса клиента только через внутренние сети прокси. Локально это отключено. После размещения стоит проверить раздельные лимиты с двух клиентских адресов: реальная цепочка прокси хостинга локально не воспроизводится.

SQLite хранит только восстанавливаемый кеш. На бесплатном тарифе он может исчезать при перезапуске; приложение создаёт его автоматически. Постоянный диск и отдельная база для нынешней версии не требуются. Коллекции сохраняются в браузере пользователя: коллекция с localhost не появится на новом домене автоматически.

## Проверка перед размещением и после него

Локальные команды для разработчика (владельцу вручную запускать их не нужно):

```sh
npm ci --include=dev
npm run check
npm test
npm run build
npm run test:production
```

`test:production` запускает настоящий `server/index.ts` на свободном порту с `HOST=0.0.0.0`, создаёт временный SQLite-кеш и проверяет HTTP: главную, JS-сборку, прямые адреса фильма и актёра, health, ошибки API и недоступность серверных файлов. Тест не загружает `.env` и не подтверждает работу живого TMDB.

После появления публичного HTTPS-адреса проверить:

- `/api/health` возвращает `ok: true` и `tmdbConfigured: true`. Последнее означает наличие ключа, а не его валидность.
- Главная показывает настоящие фильмы с постерами, поисковый запрос `Interstellar` возвращает фильм, открываются его описание и профиль актёра.
- Прямой переход и обновление `/title/movie/271110` работают без 404.
- Панель «Где смотреть» находит ссылки либо корректно сообщает об отсутствии / недоступности источника. Доступность сторонних сайтов с локального компьютера не гарантирует доступности с Render.
- На телефоне работают навигация, поиск, модальное окно и коллекция.

Ошибка `TMDB_NOT_CONFIGURED`: заполнить секрет в Environment и перезапустить сервис. `TMDB_AUTH_ERROR`: проверить, что API v3 key введён в `TMDB_API_KEY`, а длинный Read Access Token — в `TMDB_READ_ACCESS_TOKEN`, без лишних кавычек. Не публиковать содержимое переменных при диагностике.

## Ограничения бесплатной беты

Render Free засыпает после 15 минут без запросов; первое открытие после простоя может занимать около минуты. Есть месячные лимиты ресурсов и исходящего трафика; следить за Usage в панели. Бесплатный тариф предназначен для пробного размещения, а не сервиса с гарантированной доступностью. Аккаунты, серверная синхронизация коллекций и платежи в эту версию не входят.

Настройка хостинга не подтверждает права на контент сторонних сайтов. Условия использования данных и источников обсуждались отдельно; добавление рекламы или платных функций потребует возвращения к вопросу коммерческой лицензии TMDB.

Официальные инструкции: [Blueprint](https://render.com/docs/blueprint-spec), [Node.js](https://render.com/docs/node-version), [ограничения Free](https://render.com/docs/free).
